# TeleVK 0.1.1

Личный двусторонний мост **VK ↔ Telegram**. Отдельный сервис, отдельный бот и отдельная закрытая Telegram-группа с темами. Настройки и база работающего telemax не используются и не изменяются.

**Статус: первая реализация для проверяемого пилотного запуска, 4 октября 2026 года.** Код и локальные автоматические тесты включены в архив. Реальная авторизация VK, реальные отправки, работа через твой прокси и запуск на твоём сервере при подготовке этой версии не проверялись. Успешные тесты на имитированных API не являются подтверждением доступа к личным сообщениям твоего аккаунта.

## Что реализовано

| Решение | Поведение версии 0.1.1 |
|---|---|
| Отдельный сервис | Python-пакет `televk`, отдельная SQLite, пользователь и unit systemd |
| Текст, фотографии, документы | В обе стороны; подписи, авторы, даты, связь ответов |
| Неподдерживаемые сообщения | Видимое уведомление с типом; доступный текст сохраняется |
| Один чат VK — одна тема | Автоматически при новом сообщении либо вручную через `/chat` |
| Прочтение | `/read` либо направленный ответ на входящее после подтверждения отправки в VK |
| Удаление | Не реализовано; удаление в одном сервисе не удаляет копию в другом |
| История | Новые сообщения после подключения; `/history all` — вся доступная история одного чата |
| Доступ | Только заданный Telegram user ID в заданной группе; без отдельных ролей |
| `/mute` | Отключает только VK → Telegram; отправка в VK остаётся доступной |
| Обновления | Проверка при работе сервиса примерно раз в неделю и по `/updates`; никаких автоматических установок |

## Самое важное перед установкой

Нужен **пользовательский токен VK, которому действительно доступны методы личных сообщений**. Токен сообщества для этого сценария не подходит. Наличие `user` в официальной схеме метода не означает, что любые приложения могут получить необходимые права. Этот пакет не выдаёт такие права, не содержит авторизации через чужой application ID и не обходит ограничения VK.

Сначала выполняется `probe`: проверка Telegram-группы, прав бота, списка диалогов, истории и курсора сообщений VK. Отдельный `probe --send-test` отправляет тест **в «Избранное» самого авторизованного VK-аккаунта**, затем пытается прочитать его. Без успешной проверки отправки именно для текущего токена обычный `run` не запускается.

Способ получения токена и право приложения на Messaging API остаются внешней предпосылкой. В `docs/DEPLOYMENT.md` описано, что проверять и какие результаты считать достаточными. Пароли VK и токены не нужно отправлять в Telegram или в чат с помощником.

## GitHub-first установка на Linux/systemd

Начиная с 0.1.1 репозиторий является источником истины, а HTPC **не должен обращаться к PyPI**. На ПК с нормальным доступом к PyPI один раз формируется каталог `wheelhouse/` с закреплёнными portable wheel-файлами; он коммитится в GitHub вместе с кодом. Установщик проверяет SHA-256 и запускает `pip` с `--no-index`. Подробный порядок: [docs/GITHUB_WORKFLOW.md](docs/GITHUB_WORKFLOW.md).

На Windows в корне репозитория:

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\prepare-wheelhouse.ps1
git add .
git commit -m "TeleVK 0.1.1: offline wheelhouse and GitHub deployment"
git push
```

На HTPC для новой установки:

```bash
git clone <URL_ТВОЕГО_РЕПОЗИТОРИЯ> televk
cd televk
sudo bash deploy/install.sh
```

Если 0.1.0 уже успел создать `/opt/televk`, но остановился на скачивании зависимостей **до создания config.json/базы/unit**, после `git pull --ff-only` используй:

```bash
sudo bash deploy/install.sh --resume
```

`--resume` удаляет и пересоздаёт только незавершённый `/opt/televk`; `/etc/televk` и `/var/lib/televk` сохраняются. Если конфигурация, база или systemd unit уже существуют, режим намеренно откажется работать.

После успешной установки:

```bash
cd /opt/televk
sudo -u televk .venv/bin/python -m televk --config /etc/televk/config.json init
# Каталог состояния при вводе: /var/lib/televk

sudo -u televk .venv/bin/python -m televk --config /etc/televk/config.json check
sudo -u televk .venv/bin/python -m televk --config /etc/televk/config.json probe
sudo -u televk .venv/bin/python -m televk --config /etc/televk/config.json probe --send-test

# Только после успешных проверок:
sudo systemctl enable --now televk
sudo journalctl -u televk -n 100 --no-pager
```

`/updates` в 0.1.1 также не использует PyPI: крупные изменения Python-зависимостей проверяются по GitHub tags, VK schema/curl/systemd — через GitHub; локальные Python и SQLite только показываются. Ничего автоматически не обновляется.

## Команды в Telegram

Сначала в **General** отдельной группы:

```text
/help
/status
/chats
/chat 123456789 Название
```

`peer_id` берётся из `/chats`, а не из Telegram. Для бесед и сообществ идентификатор уже возвращается в нужном формате. Новые активные диалоги создают темы автоматически; `/chat` позволяет подготовить тему заранее.

В теме чата:

```text
/read
/history all
/history status
/history cancel
/mute
/unmute
/alias Новое название
```

Управление состоянием:

```text
/muted
/dlq
/retry_dlq 123
/retry_dlq 123 force
/updates
/resync
```

`/bind PEER_ID` в существующей теме полезен для ручной привязки и восстановления после неопределённого результата создания темы. Массовое автоматическое повторение неопределённых отправок не выполняется.

### Прочтение: точная семантика

Доставка копии в Telegram **не** вызывает `messages.markAsRead`. `/read` без reply использует последнее уже доставленное входящее VK-сообщение в этой теме. `/read` ответом на сообщение использует именно его границу. VK получает команду прочтения **до этой границы**, включая более ранние сообщения, а не только одного сообщения.

При обычном направленном ответе отметка ставится после подтверждения `messages.send`. При неуспешной или неопределённой отправке прочтение не ставится. Простой текст без reply не меняет отметку. Ответ на собственное исходящее не считается прочтением входящего. При отсутствии соответствия ответ передаётся текстовой цитатой, без автоматической отметки прочтения.

### История и `/mute`

`/history all` постранично получает доступную историю текущего чата, сохраняет её локально и передаёт от старых сообщений к новым с отметкой «история» и исходной датой. Фиксированного ограничения «только последние N сообщений» нет; действуют права VK и бюджеты диска/базы. Сначала выполняется сканирование, затем постановка в очередь. Новые сообщения обслуживаются независимо с более высоким приоритетом; поэтому архив может перемежаться с живой перепиской и не вставляется задним числом между уже существующими Telegram-сообщениями.

Импорт возобновляется после перезапуска. `done` в состоянии импорта означает, что доступный архив поставлен в очередь, а не обязательно полностью доставлен: общий прогресс виден в `/status`, ошибки — в `/dlq`. Изменение или удаление истории во время её чтения может нарушить полноту снимка; сверка не гарантирует восстановления удалённого.

`/mute` подавляет входящую пересылку, не запрещая ответов в VK. При включённом mute архивный импорт приостанавливается. После `/unmute` сообщения, пропущенные из-за mute, автоматически не догружаются; их можно явно запросить через `/history all`. Уже начавшаяся внешняя отправка может завершиться после команды отключения.

## Ограничения первой версии

Используется облачный Telegram Bot API. Для файлов Telegram → VK действует предел скачивания Bot API около **20 МБ**; VK → Telegram — конфигурируемый предел до **50 МБ**. Крупная фотография может быть отправлена документом. Превышение лимита становится видимой ошибкой, а не скрытым пропуском. Telegram описывает также ограничение **20 сообщений в минуту на группу**: все темы используют один общий ограничитель, поэтому большой архив идёт постепенно. Числовые лимиты реализации в коде заданы в MiB; окончательное решение всё равно принимает API. Источник: [Telegram FAQ](https://core.telegram.org/bots/faq).

Голосовые, нативное видео, стикеры, звонки и сложные виджеты не передаются в их нативном формате. Вместо них приходит описание неподдерживаемого типа. Обычный документ с аудио/видео внутри передаётся как файл. Telegram-альбом разбивается на отдельные сообщения. Редактирование существующих сообщений не синхронизируется; изменение исходящего в Telegram вызывает уведомление, а не новую скрытую отправку.

Не обещается доставка строго один раз. Если внешний API мог принять запрос, но подтверждение потерялось, задача остаётся `uncertain`; автоматический повтор остановлен. `force` может создать дубликат. Постоянный `random_id` уменьшает риск повторной VK-отправки, но не даёт бессрочной гарантии дедупликации.

Telegram хранит неполученные ботом обновления не более 24 часов. Простой дольше этого срока может привести к потере отправленных в Telegram команд/ответов до их получения мостом. Источник: [Bot API: Getting updates](https://core.telegram.org/bots/api#getting-updates).

## Как устроено

Узкий асинхронный VK-адаптер на HTTPX, Telegram Bot API через HTTPX, SQLite/WAL/FULL и четыре рабочих задачи по умолчанию. VK читается через регулярный `messages.getLongPollHistory` с сохраняемым `pts`, с интервалом 2 секунды при отсутствии продолжения; это **опрос курсорной истории**, не отдельный постоянно открытый Long Poll socket. Telegram использует `getUpdates`.

Сообщения и новый курсор фиксируются одной SQLite-транзакцией. Текст и файлы имеют отдельные задания и очереди. Есть восстановление после сбоя, ограниченные повторы, сохранение соответствий, защита от эха, бюджеты диска и общий Telegram rate limiter. Файлового persistent inbox из MAX-адаптера здесь нет: роль точки долговечности выполняет транзакция сообщения + курсор; до неё подтверждение источнику не продвигается.

Подробности и границы гарантий: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md). Источники API: [docs/SOURCES.md](docs/SOURCES.md). Протокол локальных проверок: [docs/TEST_REPORT.md](docs/TEST_REPORT.md).

## Проверка кода

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt -c constraints.txt
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python -m compileall -q televk tests
```

Тесты не требуют токенов и не обращаются к VK/Telegram. Для реального запуска нужна отдельная приёмка по `docs/ACCEPTANCE.md`.
