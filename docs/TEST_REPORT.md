# Отчёт о локальных проверках TeleVK 0.1.1

Дата: **4 октября 2026 года**. Это отчёт о фактически выполненных проверках в среде подготовки кода, а не отчёт о развёртывании у пользователя.

## Результат

**89 тестов выполнено, 89 пройдено.** После исправления гонки штатной остановки полный набор дополнительно выполнен пять раз подряд без ошибки. Использованы `unittest`, `IsolatedAsyncioTestCase`, SQLite во временных каталогах, HTTPX MockTransport и подмена внешних процессов в тестах скачивания.

Команда:

```bash
python -m coverage run --source=televk --branch -m unittest discover -s tests -v
python -m coverage report
```

Полный вывод: [test-results.txt](test-results.txt). Файл покрытия: [coverage.txt](coverage.txt).

## Среда

Python **3.13.5**, SQLite **3.46.1**, Linux. Заявленное минимальное требование к приложению — Python 3.11; отдельные прогоны на Python 3.11/3.12 в этой среде не выполнялись.

| Пакет | Установленная версия при тестировании |
|---|---|
| httpx | 0.28.1 |
| httpcore | 1.0.9 |
| anyio | 4.13.0 |
| h11 | 0.16.0 |
| idna | 3.17 |
| certifi | 2026.5.20 |
| socksio | не установлен в среде тестирования |
| typing_extensions | 4.16.0 |

SOCKS5-соединение не тестировалось. `socksio==1.0.0` включён в constraints для установки вместе с `httpx[socks]`; при заданном SOCKS-прокси `check` требует его наличия. Тесты API выполнялись через MockTransport без реального прокси.

Зависимости в контейнере уже были установлены. Чистая сетевая установка через pip здесь не выполнялась: внешнее DNS-соединение из контейнера было недоступно. Для 0.1.1 добавлен репозиторный `wheelhouse/EXPECTED_SHA256SUMS`: подготовительный скрипт на ПК обязан сверить скачанные portable wheel-файлы с этим release-манифестом до создания `SHA256SUMS`. Фактическое скачивание всех восьми wheel-файлов этим контейнером не выполнялось; оно выполняется на ПК пользователя. Установщик HTPC затем повторно проверяет манифест, запускает `pip check` и весь набор тестов.

## Дополнительные локальные проверки

`python -m compileall -q televk tests deploy/telegram_ids.py` — успешно. `bash -n deploy/install.sh tools/prepare-wheelhouse.sh` — успешно. `python -m televk --help` и `--version` — успешно; версия CLI — 0.1.1. Полный набор из 89 тестов после финального исправления также прошёл пять последовательных прогонов.

`systemd-analyze verify deploy/televk.service` разобрал unit, но завершился с кодом 1, поскольку в среде подготовки не существует `/opt/televk/.venv/bin/python`. Других сообщений эта проверка не выдала. Это **не** успешный запуск/полная верификация systemd-службы. Установщик не запускался с правами root для реального развёртывания; пользователь `televk` и сервис на сервере пользователя не создавались.

## Что остаётся проверить в живой среде

Действительность и разрешения VK-токена; доступ к конкретным беседам; фактическая семантика истории/курсора; получение всех типов реальных событий; отправка и чтение текста; загрузка файлов на действительные upload-серверы; реальное отображение reply/read; Telegram-темы и лимиты; DNS/TLS/CDN; SOCKS5 и маршруты пользователя; работа unit/watchdog; длительный простой, реальные rate limits и отзыв токена.

Процедура: [ACCEPTANCE.md](ACCEPTANCE.md). В архиве нет реальных токенов, session-файлов, пользовательской переписки или копии базы telemax.
