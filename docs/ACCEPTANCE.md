# Приёмочная проверка на реальном аккаунте

Эта таблица — **план проверки пользователем**, не отчёт об уже выполненных внешних испытаниях. При выпуске 0.1.1 реальные VK/Telegram credentials и сервер не использовались.

| Шаг | Действие | Ожидаемый результат |
|---|---|---|
| 1 | `check` | Конфигурация, права секретов, curl и SQLite проходят проверку |
| 2 | `probe` | Проверены правильная группа с темами, права отдельного бота, доступ к пользовательским диалогам, истории и курсору VK |
| 3 | `probe --send-test` | Тест появился только в «Избранном» собственного VK; `write_probe_ok=true` |
| 4 | `probe --send-test --photo ... --document ...` | Фото и документ реально открываются в «Избранном» |
| 5 | Запуск сервиса; `/status` | Стартовое сообщение, свежие времена опроса, нет ошибок конфигурации |
| 6 | Новое входящее VK от согласованного тестового собеседника | Создана или использована правильная тема, есть текст, автор и дата |
| 7 | Проверка статуса до ответа | Получение копии не должно само пометить VK-диалог прочитанным |
| 8 | Текст в теме без reply | В VK ровно одно сообщение от твоего аккаунта; есть подтверждение приёма |
| 9 | Фото и текстовый документ в обе стороны | Открываются файлы; подписи и текст не исчезают; текст не зависит от удачи загрузки другого файла |
| 10 | Голосовое или стикер в VK | Видимое уведомление о неподдерживаемом типе, а не молчание |
| 11 | Reply в Telegram на входящее | VK сохраняет ответ на нужное сообщение; прочтение ставится после подтверждения отправки |
| 12 | Reply на исходящее собственное | Входящие автоматически не отмечаются прочитанными |
| 13 | `/read` и `/read` ответом на раннее входящее | Показана граница прочтения; более новые, ещё не доставленные сообщения не выбираются мостом как граница |
| 14 | Сообщение из обычного приложения VK | Отображается как собственное сообщение; не подавляется вместе с эхом моста |
| 15 | `/mute`, новое входящее, ответ из Telegram | Входящее подавлено, ответ уходит; `/unmute` включает новые входящие без скрытой догрузки |
| 16 | `/history all` в небольшом чате | Получена доступная старая переписка, есть даты и пометка архива, новые сообщения продолжают обрабатываться |
| 17 | `/history cancel` | Импорт прекращён; уже доставленные копии не удаляются |
| 18 | Повтор `/history all` | Импорт возобновляется, известные доставленные сообщения не повторяются; ошибки файлов остаются в `/dlq` |
| 19 | Перезапуск при обычной работе/импорте | Темы, mute, соответствия и прогресс сохранены; новое подключение не создаёт всё с нуля |
| 20 | Отправка от другого Telegram-аккаунта в эту группу | В VK ничего не передано; этот тест выполнять только с согласия второго участника и без чувствительной истории в группе |
| 21 | Редактирование и удаление Telegram-сообщения | Редактирование сопровождается уведомлением без повторной отправки; удаление не переносится в VK |
| 22 | Файл больше лимита | Видимая ошибка с номером задания; не исчезает текст других сообщений |
| 23 | `/updates` | Либо сведения о версиях, либо явное `НЕ ПРОВЕРЕНО`; ничего не установлено |
| 24 | Проверка SOCKS5 на твоём сервере | Telegram API и его скачивание работают под системным пользователем `televk`, не только из твоего shell |

Тест прочтения лучше проводить так: получить первое сообщение, дождаться его в Telegram, затем остановить мост, получить второе в VK, запустить и проверить граничные случаи. Само открытие диалога в обычном клиенте VK может менять прочтение независимо от моста; не путай это с действиями TeleVK. Проверка «ещё не доставленных» сообщений зависит от фактического порядка обработки и должна опираться на конкретные ID и даты.

Проверки аварийной остановки делай только после резервной копии и на тестовом обмене. Принудительное прерывание во время внешней отправки может закономерно оставить `uncertain`. Это ожидаемая консервативная реакция, а не доказательство недоставки. Не повторяй её автоматически.

## Что не является достаточным доказательством готовности

`active (running)` не доказывает доступ к VK. `read_access=true` не доказывает отправку. Текстовый write probe не доказывает медиа. Успешная передача в «Избранное» не доказывает права на каждую беседу. Локальные тесты проверяют код на ожидаемых ответах API, но не совместимость конкретного приложения с текущими серверными ограничениями.

Для постоянного использования сначала должны пройти фактические текст, фото, документ, reply, read, mute, перезапуск и диагностика ошибок. Не использовать мост как единственную копию переписки.
